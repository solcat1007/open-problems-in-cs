# #75 支持 SUM 和 AVG 聚合的 FO 扩展

**状态**：`OPEN`
**领域**：数据库理论（聚合逻辑 / 有限模型论）
**首次提出**：作为系统性问题，成形于 1990 年代对"聚合查询逻辑"的研究（如 Hella–Libkin–Nurmonen–Wong 一系工作）[待核实：具体首倡年份]
**参与门槛**：需要新的数学工具

---

## 一句话概述

在**一阶逻辑（first-order logic, FO）**上加入 **SUM（求和）**与 **AVG（平均）**这类聚合运算符后，这个逻辑**到底能表达什么**、对它求值的**精确复杂度是多少**——是否存在一个干净的刻画？

## 形式化陈述

设有限结构 $\mathcal{A}$ 带有若干关系与数值属性。聚合逻辑的基本构造是：允许形如

$$\mathrm{SUM}_{\bar{x}}\,\bigl(t(\bar{x})\,\big|\,\varphi(\bar{x})\bigr),\qquad
\mathrm{AVG}_{\bar{x}}\,\bigl(t(\bar{x})\,\big|\,\varphi(\bar{x})\bigr)$$

的项，其中 $\varphi$ 是（可含聚合的）公式，$t$ 取数值。直观上它们把满足 $\varphi$ 的元组按 $t$ 求和 / 求平均。记带聚合的一阶逻辑为 $\mathrm{FO}(\mathrm{SUM})$、$\mathrm{FO}(\mathrm{AVG})$，并考虑其与最小不动点（LFP）等算子的组合。

**要判定的核心命题（开放）**：给出 $\mathrm{FO}(\mathrm{SUM})$、$\mathrm{FO}(\mathrm{AVG})$（及其与 LFP 的组合）**表达能力的精确刻画**，以及**数据复杂度（data complexity，把查询固定、只看数据库规模）的精确落点**。更激进的版本是：是否存在一个以聚合为核心的逻辑，恰好刻画 $\mathrm{P}$（即"逻辑刻画 PTIME"问题在聚合语境下的版本）。

## 为什么困难

### （一）SUM / AVG 在无序结构上"定义不良"

FO 的语义对结构的元素顺序**不敏感**，而 SUM、AVG 的输出**依赖顺序或至少依赖一个可加结构**。这产生一个根本张力：

- 若结构无序、无数值域，SUM 本身没有意义，必须人为指定一个序或一个数值群。
- 一旦指定了线性序，逻辑就获得了**关于序的额外能力**，表达能力会"非均匀"地膨胀，且膨胀的程度依赖序的性质（稠密 / 离散 / 有无端点）。

因此第一个困难是**语义层面的**：连"FO + SUM 是什么"都需要仔细定义，而这一定义方式直接决定后面所有复杂度结论。

### （二）从"计数"到"求和"是一道分水岭

计数（COUNT）与一阶逻辑的组合 $\mathrm{FO}(\mathrm{Cnt})$ 已有相对成熟的刻画（如两变量计数逻辑、计数量词的研究）。而 **SUM / AVG 引入了数值值域上的算术**，使逻辑能"感知"具体的数值大小，从而可以定义出用纯 COUNT 无法定义的性质。这道分水岭使得很多为 COUNT 开发的技术无法直接迁移。

### （三）与计数复杂度的耦合

一旦允许 SUM，查询求值就可能需要**对满足条件的元组做精确求和**，这与 $\#\mathrm{P}$ 一类的计数复杂度直接耦合。数据复杂度是落在 $\mathrm{AC}^0$ / $\mathrm{NC}$ / $\mathrm{P}$ / $\#\mathrm{P}$ 哪一档，取决于聚合算子与其余算子的组合方式，缺乏统一规律。

### （四）缺少"可判定性—表达能力"的通用工具

与 CSP（见 [#74](74-query-containment.md)）不同，聚合逻辑目前**没有**一个类似"同态刻画"或"代数二分"的统一工具来系统地给出二分。这使得该方向的结果高度分散，很多具体问题干脆没有已知的非平凡结论。

## 当前最好结果

| 方向 | 已知最好结果 | 出处 |
|---|---|---|
| 语义基础 | 聚合逻辑的形式语义与若干基本性质被系统建立（含与序的关系） | Hella, Libkin, Nurmonen, Wong 一系工作 [待核实：具体卷期] |
| 表达能力（有序结构） | 在有序结构上，聚合算子与不动点算子组合可显著增强表达力（如触及 PTIME 方向） | [待核实] |
| 表达能力（COUNT vs SUM） | COUNT 与 SUM 的能力存在分离，SUM 能定义纯 COUNT 无法定义的性质 | [待核实：具体分离陈述] |
| 数据复杂度 | 仅对很具体的算子组合有零散结果 | — |
| "逻辑刻画 PTIME" | **无已知非平凡结果**（聚合版本的刻画问题未获实质推进） | — |
| 精确刻画 / 二分 | **无已知非平凡结果**：不存在类似 CSP 二分的统一框架 | — |

**诚实说明**：这一方向上，公开可核查的、直接回答"$\mathrm{FO}+\mathrm{SUM}+\mathrm{AVG}$ 的精确表达能力与数据复杂度"的结果**很少**。大量相关工作是围绕 **COUNT** 或**特定聚合**在**特定结构**（尤其有序结构）下展开的，尚未汇成一个可称为"定理"的总体刻画。按本仓库的规范，此处不填充含糊措辞，明确标注：**核心命题尚无已知非平凡结果**。

## 解法现状与可行攻击路径

### 已解决的部分

- **语义框架**：聚合逻辑的基本语法与语义（包括聚合项、自由变量的处理、与序的关系）已被建立，这是后续一切工作的前提。
- **若干分离与表达能力结果**：在特定结构（尤其带线性序的结构）下，证明了某些聚合算子能定义超出基础逻辑的性质。
- **与计数逻辑的联系**：COUNT 方向的结果相对成熟，可作为 SUM / AVG 方向的参照与起点。

以上都不等于回答了核心命题。核心命题——**精确刻画 + 数据复杂度落点**——仍未被解决。

### 可行的攻击路径

| 路径 | 核心手段 | 当前状态 | 卡点 |
|---|---|---|---|
| 序敏感的语义刻画 | 明确"结构上带何种序/数值群"，据此定义聚合并刻画表达力 | 语义层已建立，表达力刻画零散 | 结论依赖序的类型，难以给出统一定理 |
| 与不动点组合 | 研究 $\mathrm{LFP}+\mathrm{SUM}$、$\mathrm{LFP}+\mathrm{AVG}$ 的捕获能力 | 有触及 PTIME 的线索 [待核实] | 是否能精确捕获 PTIME 未知；且"逻辑刻画 PTIME"本身极难 |
| 与计数复杂度对齐 | 把求值问题归约到 $\#\mathrm{P}$ 类问题并双向对照 | 只有零散归约 | 缺乏类似 CSP 的统一代数工具 |
| 分离技术 | 构造 SUM 能定义、COUNT / FO 不能定义的性质，得到能力分离 | 有若干分离 | 分离的强弱不足以拼出完整层级 |

### 已堵死的路径

- **"把 SUM 当作 COUNT 的特例"**：数值值域上的算术使 SUM 能表达 COUNT 之外的性质，这条路已被分离结果证伪。
- **"无序结构上直接谈 SUM"**：语义定义不良，这条路在形式上是行不通的，必须先补上序 / 数值结构。

暂无其它已知的原理性（barrier 级）排除结果；本方向的困难目前更多是**技术性的工具缺失**，而非被某个障碍定理封死。

### 裁决

**路径已知，尚需突破**

方向是清楚的（先固定带序的结构，再刻画表达力与数据复杂度，最后尝试与计数复杂度对齐），但核心命题——精确刻画与数据复杂度落点——**目前没有已知非平凡结果**。因此既不能算"已有部分解"，也不是"原理上受限"；归入"路径已知，尚需突破"。此处不给出任何自创解法。

## 研究路线图

- **路线一：把"结构"钉死再谈能力**。先在明确带序 / 带数值群的结构上做，逐步抽掉假设，看结论在哪里崩。这是当前最现实的推进方式。
- **路线二：与不动点算子的组合**。$\mathrm{LFP}+\mathrm{聚合}$ 是最可能触及"刻画 PTIME"的方向，但"逻辑刻画 PTIME"本身是有限模型论的世纪难题，不该被期待很快解决。
- **路线三：与计数复杂度对照**。把聚合求值归约到已知的计数问题类，做上下界夹逼。
- **路线四：分离构造**。通过"某聚合能定义而另一算子不能"的具体性质，累积出层级结构。

## 常见误区

- **误区：给 FO 加上 SUM，只是"多了一个函数"，复杂度不会变。** —— SUM 引入数值算术，使表达力与复杂度都可能跃升；把聚合当成普通函数的扩展，是低估了它。
- **误区：COUNT 的结果可以直接搬到 SUM / AVG。** —— COUNT 与 SUM 之间存在实质分离：SUM 能表达 COUNT 表达不了的性质。迁移结论必须重新证明。
- **误区：SUM / AVG 在无序结构上定义良好。** —— 一阶逻辑对元素顺序不敏感，而 SUM / AVG 依赖可加结构，必须先把序或数值结构补上，否则语义不良。
- **误区：这个方向已经有了类似 CSP 二分的统一理论。** —— 没有。聚合逻辑目前**缺少**统一的代数或二分工具，这正是它困难且结果零散的原因。
- **误区：只要找到某个"聚合版 PTIME 逻辑"问题就解决了。** —— "逻辑刻画 PTIME"本身是有限模型论的长期难题，聚合只是其中一个切入点，不是捷径。
- **误区：聚合查询只是 SQL 的工程细节。** —— 它决定了 SQL 中 `GROUP BY` / `SUM` / `AVG` 查询的**可优化性与可判定性边界**，是查询优化与视图维护的理论地基。

## 可运行实验

**`experiments/aggregate_logic_probe.py`** — 在小结构上探测量词的"序敏感性"

**思路**：实现两个小型模型检查器：(1) 一个在**无序**结构上运行的 FO（+COUNT）检查器；(2) 一个在**带线性序**的结构上运行的 $\mathrm{FO}(\mathrm{SUM})$ 检查器。对同一批小结构，分别计算若干公式的真值，并尝试构造"在有序结构上为真、在无序结构上无定义 / 不可表达"的公式。

**能观察到什么**：你会直观看到"序的引入"如何让原本无法表述的性质变得可表述——这正是本问题为什么必须先从语义层入手的具体体现。

**不能说明什么**：

- 这只是**有限规模**上的真值计算，**完全不能**证明任何表达力分离定理或复杂度结论——表达力命题是关于**所有结构**的陈述。
- 它无法替代 Hella 等工作中真正的组合 / 代数论证。
- 它触及不到"逻辑刻画 PTIME"这一核心难题。
