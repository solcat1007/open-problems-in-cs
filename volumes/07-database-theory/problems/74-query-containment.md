# #74 查询包含问题

**状态**：`OPEN`
**领域**：数据库理论（查询语言 / 有限模型论）
**首次提出**：Ashok K. Chandra 与 Philip M. Merlin，1977（STOC 1977；同名工作有 1981 年版本）
**参与门槛**：需要新的数学工具

---

## 一句话概述

给定两条查询 $Q_1$ 与 $Q_2$，判断"在**任何**数据库上，$Q_1$ 给出的结果都被 $Q_2$ 的结果包含"是否成立——也就是判断 $Q_1 \subseteq Q_2$。

## 形式化陈述

固定一个关系模式（relational schema）$\sigma$。一个**合取查询（conjunctive query, CQ）**形如

$$Q(\bar{x}) \; := \; \exists \bar{y}\,\bigl(R_1(\bar{u}_1) \wedge \cdots \wedge R_m(\bar{u}_m)\bigr),$$

其中 $\bar{x}$ 是**头部（head）变量**（查询的输出列），$\bar{y}$ 是**存在量词约束（existential）变量**。把 $\exists \bar{y}$ 部分称为查询的**主体（body）**。

**查询包含（query containment）**：

$$Q_1 \subseteq Q_2 \quad\overset{\text{def}}{\iff}\quad \forall D,\; Q_1(D) \subseteq Q_2(D),$$

其中 $D$ 遍历所有满足模式的有限数据库，$Q_i(D)$ 是查询在 $D$ 上返回的元组集合。

**核心判定问题**：给定 $Q_1, Q_2$，判定 $Q_1 \subseteq Q_2$ 是否成立。

**Chandra–Merlin 归约（同态刻画）**：对不含不等式的 CQ，$Q_1 \subseteq Q_2$ 当且仅当存在一个从 $Q_2$ 主体到 $Q_1$ 主体的**同态（homomorphism）**$h$，使得 $h$ 把 $Q_2$ 的头部变量映射到 $Q_1$ 对应的头部变量。这个同态称为**包含映射（containment mapping）**。于是包含判定化归为"找一个满足若干等式的变量赋值"，即一次非确定性猜测加多项式验证。

**复杂度版本区分（关键）**：包含问题的答案随查询语言的细节而变，必须分开陈述：

| 版本 | 复杂度 | 出处 |
|---|---|---|
| 布尔合取查询（无投影） | **NP 完全** | Chandra–Merlin 1977 |
| 合取查询（允许投影） | 由包含映射刻画；不等式无关情形下仍为 **NP 完全** | Chandra–Merlin 1977；Aho–Sagiv–Ullman 1979 |
| 含不等式 $\neq$ 的合取查询 | 仍为 **NP 完全** | Klug 1988 |
| 允许投影且带序/算术比较（有序域）的一般情形 | 复杂度上移至 **$\Pi^P_2$ 完全** | [待核实：精确版本与归因，通常追溯到 Chandra–Merlin 1981 及后续工作；不同文献对"投影"与"序关系"哪一个触发上移的口径不完全一致] |

这里必须强调：**"布尔"与"带投影"是两个不同的问题版本**，"含不等式"又是一个维度。把这三者混为一谈，是本领域最常见的表述错误。

## 为什么困难

### （一）上界一侧其实很清楚，难的是"边界"

对 CQ 这一层，包含问题的**判定性**早在 1977 年就已经解决，复杂度也已刻画到 NP 完全。因此这个问题的"难"不在 CQ 本身，而在于：**把边界从 CQ 往外推一格，落到哪里？**

已经知道两端的答案：完全的一阶关系演算（含否定）的包含问题是**不可判定**的（这是经典结论，与一阶逻辑在有限模型上不可判定同源）。而在 CQ 一侧是 NP 完全。中间那一大片——含受限否定、含聚合、含递归（Datalog）、在完整性约束下求包含——**各自是否可判定、精确复杂度落在哪一档，至今没有统一图景**。这就是 #74 仍然标为 `OPEN` 的真正含义。

### （二）约束（依赖）的加入会同时改变判定性与复杂度

现实中的查询不是孤立比较的，而是在一组合法性约束（函数依赖 FD、元组生成依赖 TGD、元组否定依赖 EGD 等）下比较。此时 $Q_1 \subseteq Q_2$ 要理解为"在所有满足约束的数据库上成立"。约束的加入会让包含问题从"一个同态搜索"变成"在约束闭包上判定蕴含"，复杂度普遍上升；**对很多约束类，是否可判定都还是开放问题**。

### （三）与约束满足问题的深层耦合

Kolaitis 与 Vardi 指出：**CQ 包含等价于一类约束满足问题（CSP, constraint satisfaction problem）**。于是 CSP 复杂度理论的全部成果——包括 Feder–Vardi 二分定理猜想——都直接作用到包含问题上。这一点既是本册的中心视角（见 [本册 README](../README.md)），也是把 #74 与复杂性理论主干连通的那根线。

## 当前最好结果

| 方向 | 已知最好结果 | 出处 |
|---|---|---|
| 判定性（CQ） | 合取查询包含可判定，由包含映射刻画 | Chandra–Merlin 1977 |
| 上界（CQ） | CQ 包含 ∈ NP；含不等式情形 ∈ NP | Chandra–Merlin 1977；Klug 1988 |
| 下界（CQ） | CQ 包含是 NP 难的，故为 NP 完全 | Chandra–Merlin 1977 |
| 下界（含不等式） | 含不等式 CQ 包含仍是 NP 完全 | Klug 1988 |
| 上移情形 | 一般（含投影 / 有序域）版本达到 $\Pi^P_2$ 完全 | [待核实] |
| 与 CSP 的等价 | CQ 包含可化归为 CSP；固定一侧查询时复杂度由关联 CSP 决定 | Kolaitis–Vardi 2000 |
| 固定查询的二分 | 关联 CSP 可解 ⇒ 包含在 P 中；否则 NP 完全（由 Feder–Vardi 猜想解决而导出） | Feder–Vardi 1998；Bulatov 2017；Zhuk 2017/2020 |
| 一般（非 CQ）情形 | **开放**：介于 CQ 与一阶演算之间的查询类，判定性与精确复杂度未完全刻画 | — |

**注意"精确刻画"与"上界/下界"的区别**：CQ 情形我们拥有的是**精确二分**——要么 P，要么 NP 完全，没有中间档。这种"精确二分"正是本册的关键词；而一般查询类连一个确定的判定性结论都还没有。

## 解法现状与可行攻击路径

### 已解决的部分

- **CQ 包含本身**：判定性与复杂度均已封顶（NP 完全），并给出同态刻画（Chandra–Merlin 1977）。
- **含不等式 $\neq$ 的 CQ 包含**：Klug 1988 证明其仍为 NP 完全，堵住了"加不等式会让问题暴涨"的直觉。
- **与 CSP 的等价**：Kolaitis–Vardi 2000 把 CQ 包含（含不等式版本）精确地对应到 CSP，从而把包含问题接入 CSP 二分理论。
- **固定左侧查询的二分**：通过上述等价，Feder–Vardi 猜想（已由 Bulatov 与 Zhuk 独立证明）给出了"固定一个查询、判定它是否被另一个 CQ 包含"这一问题的**完整二分**：对每个查询模板，该问题在 P 中或为 NP 完全。

### 可行的攻击路径

| 路径 | 核心手段 | 当前状态 | 卡点 |
|---|---|---|---|
| CSP 归约 + 二分 | 把包含实例编码成 CSP 实例，套用 Bulatov–Zhuk 的二分 | 固定模板版本已完全二分 | 两边都变动的版本不在二分覆盖范围内 |
| 约束下的包含 | 用 chase（追赶）构造约束下的"通用解"再做包含检查 | 对若干 TGD/EGD 类有结果 | 约束类一扩，可判定性即失守；边界未画出 |
| 受限否定 / 聚合片段 | 对含受限否定的片段、含聚合的包含做单独分类 | 零散结果 | 缺少统一代数工具；聚合情形几乎空白 |
| 视图重写（view rewriting） | 把"能否用视图回答查询"等价为包含测试 | 大量具体算法（如 bucket / inverse rules） | 递归视图与含算术情形难以统一 |

### 已堵死的路径

- **含一般否定的完整演算**：包含问题**不可判定**（与一阶逻辑有限模型上的不可判定同源），因此"给一个通用算法"这条路已被堵死。
- **纯语法（句法）比较**：靠查询书写形式做等价判断在 CQ 之外绝大多数语言上不成立，已被包含映射的反例反复证伪。

### 裁决

**已有部分解**

CQ 层（含不等式）已被完整解决并精确二分；固定模板版本借助已解决的 Feder–Vardi 猜想得到完整二分。开放的是**介于 CQ 与一阶演算之间的中间层**——含受限否定、聚合、递归，以及约束下的包含——其判定性与精确复杂度尚未统一刻画。此处只陈述现状，不给出任何自创解法。

## 研究路线图

- **路线一：二分化**。把包含问题按查询语言结构做完全分类，目标是"对每个自然片段，要么 P 要么 NP/coNP 完全"。这是本册的中心方法论。
- **路线二：约束下的包含**。研究在不同依赖类（FD、TGD、EGD 及其组合）下包含问题的可判定性与复杂度，画出"可判定 / 不可判定"的分界。
- **路线三：代数与视图重写**。把包含测试转成查询改写算法，落到优化器里。
- **路线四：聚合与递归**。这两类目前几乎是空白区，属于"无已知非平凡结果"的边缘。

## 常见误区

- **误区：查询包含是一个纯工程问题，与理论无关。** —— 恰恰相反，**视图重写、查询优化、数据交换、语义查询优化**的核心算法都建立在包含判定之上。
- **误区：包含问题的复杂度就是一个数，比如"NP 完全"。** —— 复杂度**随版本而变**：布尔 CQ、带投影 CQ、含不等式 CQ 都是 NP 完全，而允许序关系 / 一般投影的版本会升到 $\Pi^P_2$ 完全。不加限定的"包含是 NP 完全的"就是错的。
- **误区：CQ 包含解决了，所以整个包含问题解决了。** —— CQ 之外（含否定、聚合、递归、约束）大片区域仍未刻画；一般情形甚至不可判定。这正是本问题标为 `OPEN` 的原因。
- **误区：加不等式一定让问题变得更难。** —— Klug 1988 表明含 $\neq$ 的 CQ 包含**仍然是 NP 完全**，并没有跳档。难度的跳变发生在"序 / 算术比较 + 投影"这类组合上，而不是单纯加 $\neq$。
- **误区：查询等价与查询包含是同一个问题。** —— 等价是 $Q_1 \subseteq Q_2$ 与 $Q_2 \subseteq Q_1$ 的合取，复杂度同阶，但表述不同，不能混用。
- **误区：固定查询的一侧与两边都变是一回事。** —— 二分定理说的是**固定一侧模板**时的完整分类；两边同时作为输入时落在二分理论覆盖范围之外，需单独分析。

## 可运行实验

**`experiments/cq_containment.py`** — 小规模 CQ 包含的暴力判定与同态判定对照

**思路**：在很小的模式（1–2 个关系、若干元组）上做两件事：

1. **暴力语义判定**：枚举一个足够大的有限域上的所有小数据库，逐一代入 $Q_1$ 与 $Q_2$，检查是否存在反例数据库使 $Q_1(D) \not\subseteq Q_2(D)$。这是直接按照包含的**定义**（$\forall D$）做的判定。
2. **同态判定**：按照 Chandra–Merlin 刻画，在 $Q_2$ 主体与 $Q_1$ 主体之间枚举所有变量赋值，检查是否存在满足头部约束的包含映射。

**能观察到什么**：在随机生成的小 CQ 对上，两个判定应给出**一致**的结论。这直接验证了"包含 $\iff$ 存在包含映射"这一已知定理，并让"NP 完全"背后那个"猜一个映射"的算法变得可见。

**不能说明什么**：

- 有限规模的枚举**无法**证明任何渐近复杂度结论，也无法推出 NP 完全性。
- 暴力判定只在**极小有限域**上枚举，而包含是对**所有有限数据库**（含任意大）成立的；因此"没找到反例"不等同于包含成立——真正给出结论的是同态判定，暴力判定只用于交叉验证。
- 它触及不到约束、聚合、递归等真正开放的版本。
