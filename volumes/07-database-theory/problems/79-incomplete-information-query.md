# #79 不完全信息下的查询应答

**状态**：`OPEN`
**领域**：数据库理论（不完全信息 / 数据交换）
**首次提出**：不完全信息数据库研究始于 1980 年代（Imielinski–Lipski 一系）[待核实：具体首倡]；确定答案的系统化随数据交换工作（Fagin 等 2005）而成型
**参与门槛**：需要新的数学工具

---

## 一句话概述

当一个数据库**不完整**（有缺失值、有多种可能的补全）时，一条查询的**确定答案（certain answers）**——在所有可能补全上都成立的那些答案——能否被高效计算？它又落在哪个复杂度档？

## 形式化陈述

**不完全数据库**：一个数据库实例 $D$ 中可能含有**未知值**。常见模型：

- **空值模型（nulls）**：某些位置是"未知但存在"的值。
- **条件表（c-tables）**：每个未知位置附带一组条件，条件成立时该位置取对应值。
- **可能世界语义**：$D$ 代表一族**可能世界（possible worlds）**$\mathrm{Mod}(D)$，即所有把它补全为完整实例的方式。

**确定答案（certain answers）**：

$$\mathrm{certain}(Q, D) \;=\; \bigcap_{W \in \mathrm{Mod}(D)} Q(W),$$

即：一条答案被"确定地"接受，当且仅当它在**每一个**可能世界上都出现。

**加入约束**：若还有一组完整性约束 $\Sigma$（FD、TGD、EGD 等），则 $\mathrm{Mod}(D)$ 只保留满足 $\Sigma$ 的补全。

**要判定的核心命题（开放）**：给定查询类与信息 / 约束模型，**精确刻画**计算 $\mathrm{certain}(Q, D)$ 的复杂度：

- 对哪些 $(\text{查询类},\ \text{信息模型},\ \text{约束类})$ 组合，确定答案可在 $\mathrm{P}$ 中计算？
- 对哪些组合，它跳到 coNP 完全（乃至更高）？
- 是否存在一个**统一二分**？

## 为什么困难

### （一）"对所有可能世界取交集"本身就是共 NP 结构

确定答案要求"**对每一个**补全都成立"。这是一个全称量词，因此**上界**通常在 coNP 中（猜一个反例世界并验证）。问题几乎总是"上界易、下界难"——二分定理的困难集中在**为每个未落入 P 的组合构造 coNP 难度归约**。

### （二）可能世界的数量是指数的，且模型之间不通用

空值模型与 c-table 模型给出的可能世界集合**结构不同**，确定答案的难度也随之不同。**同一查询在不同不完全信息模型下可以得到不同的复杂度结论**，因此不能笼统地问"确定答案多难"，必须把信息模型一并钉死。

### （三）约束的加入会同时改变语义与复杂度

加入 TGD / EGD 后，可能的补全必须满足约束，这通常使可能世界集合变小，却**不一定**让问题变简单——约束的蕴含检查本身就难。数据交换（data exchange）理论用 **chase（追赶）**与**通用解（universal solution）**来处理这一点，但 chase 未必终止，**终止性本身也是开放问题的一部分**。

### （四）查询类的表达能力直接抬高难度

- 对**合取查询（CQ）**，确定答案可由"对通用解求值再取交集"处理，方法相对成熟。
- 一旦查询含**否定、析取、聚合**，确定答案的计算普遍跳档，且缺乏统一工具——这正是开放区域的主体。

### （五）与包含问题、CQA 的技术内核重合

判定"某元组是否在所有补全 / 修复中出现"，与 [#74 查询包含](74-query-containment.md)、[#76 软修复](76-soft-repair-dichotomy.md) 是同一类"**约束下判定蕴含**"的问题。因此 #79 继承了这条链上的全部开放点。

## 当前最好结果

| 方向 | 已知最好结果 | 出处 |
|---|---|---|
| 上界（CQ + 一般不完全信息） | 确定答案 ∈ coNP（猜反例世界并验证） | 标准结论 |
| CQ + 空值 / c-table | 确定答案计算可化归为在 c-table 上求值；对 CQ 通常为 coNP 完全 | 经典结论（不完全信息数据库一系）[待核实：精确出处] |
| 数据交换 + 无目标依赖 / 弱依赖 | 对 CQ，确定答案可由**通用解**计算，落在 $\mathrm{P}$ | Fagin 等 2005 |
| 数据交换 + 一般 TGD + EGD | 用 chase 与通用解框架处理；chase 可能不终止 | Fagin 等 2005 及后续 |
| 查询含否定 / 聚合 | 多数组合下复杂度上移，完整刻画缺失 | — |
| 统一二分 | **开放**：不存在覆盖一般 $(\text{查询类},\ \text{信息模型},\ \text{约束类})$ 的完整二分 | — |

**区分"上界 / 下界 / 精确刻画"**：数据交换 + CQ 的 $\mathrm{P}$ 是**精确结果**；一般不完全信息 + CQ 的 coNP 完全也接近精确；但一旦引入否定 / 聚合 / 复杂约束，多数组合只有上界或零散下界，**没有精确刻画**。

## 解法现状与可行攻击路径

### 已解决的部分

- **数据交换 + CQ + 弱依赖**：确定答案可由**通用解**（或 core）计算，落在 $\mathrm{P}$，这是本方向最干净的结果（Fagin 等 2005）。
- **c-table 上的 CQ 求值**：把确定答案的计算精确对应到在 c-table 上求值，给出了 coNP 完全性的技术路径。
- **chase 与通用解框架**：为"约束下的可能世界"提供了统一的构造工具，是后续一切工作的基础。

### 可行的攻击路径

| 路径 | 核心手段 | 当前状态 | 卡点 |
|---|---|---|---|
| 通用解 / core | 构造约束下的通用解，对 CQ 求值再取交集 | 弱依赖下成功 | 一般 TGD + EGD 下 chase 可能不终止，通用解未必存在 |
| 二分化 | 按查询类 / 约束类逐格切分，定复杂度 | 零散结果 | 网格维度多，分类爆炸 |
| c-table 代数 | 把确定答案化为 c-table 上求值，借 #P / coNP 工具 | 对 CQ 有效 | 含否定 / 聚合时失效 |
| 与包含问题联动 | 复用"约束下蕴含"的判定算法 | 部分可用 | 约束下蕴含本身开放（见 #74） |

### 已堵死的路径

- **"用某一个信息模型通吃所有结论"**：空值、c-table、数据交换三类模型给出的复杂度不同，把结论跨模型搬运会出错。
- **"chase 总能终止，所以通用解总存在"**：一般 TGD + EGD 下 chase 可能不终止，这条路不成立。
- **"确定答案 = 对某个'代表实例'求值"**：只有在通用解存在且查询是 CQ（对并 / 某些算子封闭）时才成立，一般情形不成立。

暂无类似"相对化障碍"那样的原理性排除结果；困难主要是**组合结构的复杂性与工具缺失**。

### 裁决

**路径已知，尚需突破**

方向明确：用通用解 / chase 处理 CQ，用 c-table 代数处理缺值，再逐步逼近否定与聚合。数据交换 + CQ 已有精确的 $\mathrm{P}$ 结果；但一般 $(\text{查询类},\ \text{信息模型},\ \text{约束类})$ 的统一刻画仍是开放的。归入"路径已知，尚需突破"。此处不给出任何自创解法。

## 研究路线图

- **路线一：把 CQ 结果往外推**。从 CQ 扩展到并合取查询、含不等式查询、含受限否定的查询，看确定答案的复杂度如何变化。
- **路线二：约束的终止性**。刻画"哪些依赖类的 chase 终止 / 存在通用解"，这是判定 $\mathrm{P}$ 侧的边界。
- **路线三：二分化**。把"查询类 × 信息模型 × 约束类"的网格逐格填上复杂度，目标是给出完整二分。
- **路线四：与 OBDA / 知识图谱联动**。本体的查询应答（ontology-based query answering）正是不完全信息查询应答在语义网场景下的直接应用，工程需求会反哺理论。

## 常见误区

- **误区：不完全信息就是"某些字段为空"。** —— 空值只是最弱的模型。真正的语义在于**可能世界的集合**：空值、c-table、数据交换给出的可能世界结构不同，确定答案的难度也不同。
- **误区：确定答案就是"多数可能世界都同意"的答案。** —— 确定答案是**所有**可能世界的交集，是严格的全体一致，不是多数表决；这与 [#76](76-soft-repair-dichotomy.md) 的硬一致语义同源。
- **误区：只要有缺失信息，问题就一定很难。** —— 反例就在数据交换 + CQ + 弱依赖：确定答案可在 $\mathrm{P}$ 中计算。难度取决于**查询类与约束结构**，而非是否有缺值。
- **误区：chase 一定会终止。** —— 一般 TGD + EGD 下 chase 可能不终止，通用解也因此未必存在；这是本方向的核心技术障碍之一。
- **误区：把 coNP 上界当成 coNP 完全。** —— 上界（∈ coNP）与下界（coNP 难）是两件事，"能猜反例验证"只给出上界。
- **误区：不完全信息查询应答只与学术有关。** —— 数据集成、知识图谱、本体查询应答（OBDA）、缺失数据填补，都是它的直接应用场景。

## 可运行实验

**`experiments/certain_answers_enumeration.py`** — 小实例上的确定答案枚举

**思路**：构造小规模的不完全数据库（含空值 / c-table）：

1. **枚举所有可能世界**（把所有未知位置在足够大的有限域上填满），保留满足给定约束的那些。
2. 对每个世界求查询结果，**取交集**得到确定答案——这是按定义直接做的判定。
3. 系统改变(查询类)(约束类)(信息模型)，观察确定答案集合大小与枚举开销的变化，并与"使用通用解"的方法对照。

**能观察到什么**：你会看到确定答案如何在指数多个可能世界的交集中浮现，以及约束如何既缩小可能世界集合、又让判定变难——这正是本问题核心张力的具体表现。

**不能说明什么**：

- 有限枚举**不能**证明任何 coNP 难度或可解性结论；那些是关于**所有**实例的命题。
- 观察到的"某约束下变慢"只是小规模现象，不能替代 coNP 难度归约。
- 它触及不到 chase 终止性等核心理论问题。
