# #91 生命之树估计

**状态**：`PARTIAL`
**领域**：计算生物学 / 系统发育学
**首次提出**：树状进化思想可追溯至 Darwin，1859；作为统计估计问题可追溯至 Edwards 与 Cavalli-Sforza（1964）与 Neyman（1974，分子数据下的极大似然）
**参与门槛**：可以立刻上手做实验

---

## 一句话概述

为地球上所有已知物种重建一张统一的进化树——推断"谁与谁的共同祖先更近"——问题是：不同数据与方法给出的树**互不一致**，且我们没有任何独立途径确认"正确答案"长什么样。

## 形式化陈述

给定 $n$ 个分类单元（物种或基因组）及其同源分子序列数据 $D$，以及一个序列演化模型（如 Jukes-Cantor 1969、Kimura 1980 等替代模型），问题分为三层：

1. **推断层**：寻找系统发育树 $T$（拓扑 + 枝长 + 模型参数），使似然 $L(T \mid D)$ 在给定模型下最大（极大似然，ML），或给出后验分布（贝叶斯框架）。
2. **复杂性层**：对固定替代模型，ML 建树已被证明是 NP 难的（Roch, 2006；期刊出处 [待核实]）。树上拓扑数为 $(2n-5)!!$，随 $n$ 超指数增长。
3. **一致性层**：在真实演化过程符合假设模型时，推断方法是否统计一致（样本趋长时收敛到真树）。Felsenstein（1981）证明 ML 在一定条件下一致；但存在演化情形（"长枝吸引"）使简约法等自然方法以正概率收敛到**错误**的树（Felsenstein, 1978）。

更根本的困难在于：**问题本身可能没有良好定义的对象**。生命历史包含水平基因转移（HGT）、杂交多倍化与不完全谱系分选（ILS），使"每个物种一张唯一真树"的预设只对部分基因组区域成立——"生命之树"更准确说是"估计一组基因树背后的物种树（或网络）"，已非单一优化问题。

## 为什么困难

**（一）计算不是主要瓶颈。** ML 建树虽 NP 难，但 RAxML（Stamatakis, 2014）、IQ-TREE（Nguyen et al., 2015）已在常规硬件上处理数千乃至上万分类单元，**复杂性意义上的"难"已被工程压住**，真正卡点在下面三层。

**（二）模型不匹配。** Jukes-Cantor、Kimura、Neyman（1974）等是高度简化的马尔可夫过程，而真实演化中替代率在位点间、枝系间高度异质。跨位点异质精细模型（Lartillot & Philippe, 2004）能缓解部分问题，但模型越细计算越贵，且对真实数据的假设仍无法满意地检验。

**（三）基因树 ≠ 物种树。** 同一基因组中不同基因的谱系历史可以因 ILS、HGT 与基因丢失而互不相同。这意味着"从数据中估计一棵树"的前提——数据背后存在单一树——对全基因组数据**不成立**。这不是算法缺陷，而是**对象本身的性质**：需要估计的是多个历史过程的叠加，而非单一对象。

**（四）长枝吸引与不一致性。** Felsenstein（1978）证明：在特定演化速率组合下，简约法会以正概率收敛到错误拓扑，且序列越长错得越"自信"。这排除了"最简约的树就是真树"这条直觉路线：**方法的数据表现好，不代表方法的统计性质正确**。

**（五）没有真值。** 我们无法为任何一组真实物种独立验证树拓扑——化石、形态学与分子数据各有偏差且互不一致。这使本问题与 Vol.01 的数学问题有本质区别：连"对错"都要靠推断链本身来定义。

## 当前最好结果

| 方向 | 已知最好结果 | 出处 |
|---|---|---|
| 算法（ML） | RAxML 支持大规模数据下的快速 ML 建树（定性：常规处理数千至数万分类单元） | Stamatakis, 2014 |
| 算法（ML/贝叶斯） | IQ-TREE 的模型选择与快速 Bootstrap；MrBayes 的通用贝叶斯推断 | Nguyen et al., 2015；Ronquist et al., 2012 |
| 统计性质 | ML 在替代模型假设成立时统计一致 | Felsenstein, 1981 |
| 不一致反例 | 简约法在特定速率组合下不一致（长枝吸引） | Felsenstein, 1978 |
| 复杂性 | 固定模型下 ML 建树 NP 难 | Roch, 2006（出处 [待核实]） |
| 全基因组重构 | 用数千基因组数据对原核生命之树的大规模重构（Hug et al., 2016 的"新生命之树"），但树内部多个深处分叉仍不稳定 | Hug et al., 2016, *Nature Microbiology* |
| 物种树方法 | 基于溯祖模型的物种树推断（如 ASTRAL，Mirarab et al., 2014），在 ILS 主导的情形下有理论依据 | Mirarab et al., 2014 |

**关于上表必须强调**：Hug et al. (2016) 的重构是**当前对原核生命历史的最好估计之一**，但其自身明确指出多个深部节点支持度不足；"重构出一棵树"与"重构出正确的树"之间的距离无法量化——因为没有真值可用。

## 解法现状与可行攻击路径

### 已解决的部分

以下子问题在给定假设下被真正解决：

1. **给定替代模型与序列的小规模 ML/Bayes 推断**：Felsenstein（1981）的剪枝算法使似然计算成为多项式时间（对固定树），"算似然"这一步是彻底解决的。
2. **距离法的基础**：Neighbor-Joining（Saitou & Nei, 1987）在特定演化模型条件下统计一致，且速度快。
3. **支持度量化**：Bootstrap 支持度（Felsenstein, 1985）为拓扑不确定性提供了可复现的度量——注意它度量的是"数据对拓扑的支持强度"，不是"拓扑是否正确"。
4. **ILS 主导情形下的物种树推断**：在溯祖模型假设下，基于多基因树的方法（ASTRAL 等，Mirarab et al., 2014）有理论一致性保证。**条件性**结论：假设基因树误差可忽略、演化由 ILS 主导、无 HGT。

### 可行的攻击路径

| 路径 | 核心手段 | 当前状态 | 卡点 |
|---|---|---|---|
| 精细替代模型 | 跨位点异质混合模型（Lartillot & Philippe, 2004）等 | 已实现并应用于深部系统发育 | 计算代价高；对真实过程的假设仍不可验证；模型选择本身不确定 |
| 基因树–物种树调和 | 溯祖模型 + 多基因树汇总（ASTRAL 等） | 已成熟并广泛使用 | 基因树自身有错误且错误会被传递；对 HGT 与杂交的建模不足 |
| 系统发育网络 | 用网络（有向无环图）替代树表示 HGT/杂交 | 概念框架与若干推断方法存在 | 网络空间组合爆炸；推断方法远不如建树成熟；结果解释困难 |
| 更大数据 + 基因组尺度采样 | 基因组测序扩展分类单元覆盖（如 Hug et al., 2016） | 持续推进中 | 深部节点的信息量不随样本数线性增长；缺失数据与测序偏差引入系统误差 |
| 模拟与基准评估 | 用模拟演化数据检验方法性质 | 已是标配 | 模拟无法涵盖真实进化的全部复杂性，"在模拟中一致"不保证在真实数据上一致 |

### 已堵死的路径

本问题没有复杂性理论意义上的"障碍"，但有一条**被反例排除的直觉路线**：

- **简约法作为一般方法**：Felsenstein（1978）证明在长枝吸引情形下简约法统计不一致。这不是说简约法无用（在相近类群间它仍有竞争力），而是说"不必建模型、最简约即真"作为**一般原理**已被排除。

除此之外，暂无已知的原理性排除结果。需警惕一条**方法论上的死胡同**：把某个数据集上的 Bootstrap 高支持度当作"树已确定"的证据——它只度量数据强度，不度量模型与方法的正确性。

### 裁决

**`已有部分解`**

单基因、模型假设成立的小规模建树已有成熟方法与统计理论；全基因组、跨生命域的"生命之树"则受制于基因树不一致、HGT 与无真值可依，处于"多棵互不一致的候选树并存"状态。归入本档：子问题的解决是实质性的，但核心问题（统一、可信、可检验的全局树）没有任何方法能给出。

## 研究路线图

**路线一：扩大采样与数据整合。** 基因组测序持续填补类群空白（Hug et al., 2016）。现状：近期分叉分辨率提升；**卡点**：深部节点在数据量增加下仍摇摆，说明问题在信号的古老与稀薄而非数据量。

**路线二：从树到网络。** 承认生命历史部分非树形，发展系统发育网络推断。现状：概念框架成型、方法可用性差。**卡点**：网络推断的搜索空间与可辨识性远未解决。

**路线三：联合建模基因树与物种树。** 在一个模型中同时推断两者，避免基因树错误传播。现状：溯祖框架下有进展。**卡点**：模型复杂度与计算代价；HGT 仍被多数框架排除。

**路线四：检验而非只推断。** 用形态、化石校准、分子交叉检验同一节点。现状：实践常态。**卡点**：证据来源偏差不同，冲突裁决需元方法。

## 常见误区

- **误区：生命之树已经画好了，只是没公开。** 实际是**没有单一真值**——不同数据类型与方法给出互不一致的树，这是**方法论与对象层面的分歧**（基因树 vs 物种树、ILS 与 HGT），不是工程延迟。

- **误区：只要算力够大，就能算出正确的树。** ML 搜索非瓶颈（RAxML/IQ-TREE 已处理上万分类单元）；瓶颈在模型不匹配与历史本身非单棵树，加算力改不了统计不一致带来的系统错误。

- **误区：Bootstrap 支持度高，说明树是对的。**
  Bootstrap 度量"重采样下拓扑的稳定程度"，即在当前方法与模型假设内数据对拓扑的支持强度。模型错了、数据有系统偏差时，Bootstrap 可以对错误拓扑给出极高支持度。

- **误区：树就是生命的历史。** HGT（原核生物中大量存在）、杂交多倍化与 ILS 使相当部分真实历史非树形；树是对历史的**近似或投影**，部分节点上这一近似不合格。

- **误区：不同研究给出不同的树，说明有人犯了错。**
  并非必然。用不同基因、分类单元组合与模型，得到不同拓扑可以是**各自的正确输出**——分歧本身是关于"生命历史是否为树"这一问题的信息。

## 可运行实验

**`experiments/phylogenetic_tree_demo.py`**

在普通电脑上可完成：按**已知**合成树 + Jukes-Cantor 模型模拟小规模（10–30 分类单元）序列；用自实现的 Neighbor-Joining 与 UPGMA 从距离矩阵建树；用 Robinson–Foulds 距离比较重建树与真树；对建树做 Bootstrap 重采样观察支持度分布。

**能观察到什么**：序列足够长时 NJ 能稳定还原真树（对应 Felsenstein 1981 的一致性直觉）；序列短时，Bootstrap 支持度在错误分支上也可能很高；引入速率异质（长枝）后，重建开始系统性偏离（长枝吸引的可感知版本）。

**不能说明什么（重要）**：本实验使用合成数据与最简模型，**不构成对真实生命之树任何节点的验证**，也不是对 RAxML/IQ-TREE 等成熟软件的替代。它演示的是"一致性、支持度、长枝吸引"三个概念的力学，不是领域结论。
